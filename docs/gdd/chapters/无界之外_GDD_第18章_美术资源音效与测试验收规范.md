### 18.0 本章范围与设计基线

本章定义《无界之外》美术资源、音效、文件命名、目录结构、图集压缩、机型适配、帧率内存目标、网络压测与功能验收规范，作为资源制作、导入与验收的基线。

本章不定义玩法规则（第2–15章）、界面交互细节（第16章）与服务端协议（第17章）。资源制作必须遵循原创Q版奇幻风格，禁止复制受版权保护的第三方素材。

**设计基线：**

1.  美术风格为原创Q版奇幻风格，统一世界观与视觉语境。
2.  所有未确定的数值（纹理格式、压缩比、帧率、内存预算等）标注为「待技术美术确定 / 待压测确定」，不在此编造硬指标。
3.  资源命名与目录结构必须统一，否则不得进入正式资源包。

## 18.1 角色资源规格

**优先级：【MVP必须】**

### 【功能说明】

定义角色美术资源交付要求，引用第3章3.9的交付清单，确保客户端按角色配置加载模型与动画。

### 【规范】（引用第3章3.9交付清单）

每个角色至少交付：角色头像、角色模型、待机动画（IDLE）、8方向移动动画（MOVE）、交互动画（INTERACT）、角色预览资源、挥手（ACT_001）、点头（ACT_002）、开心（ACT_003）、疑问（ACT_004）。

### 【要求】

  项目            规范
  --------------- --------------------------------------------------
  资源命名        `CHR_{角色编号}_{资源类型}_{动作}_{方向}_{序号}`
  交付目录        `characters/CHR_001/{model,animation,portrait,preview}`
  状态一致性      动画状态名称遵循第3章3.4统一映射
  授权合规        模型/贴图须有合法授权，禁止复制第三方素材

### 【验收标准】

1.  12个角色均能通过资源ID正确加载。
2.  每个角色包含规定基础动画资源。
3.  缺失资源能被日志准确定位（第3章3.9）。

## 18.2 角色动画状态

**优先级：【MVP必须】**

### 【功能说明】

明确角色动画状态机与动作编号，关联第3章3.4的IDLE/MOVE/INTERACT/LOCKED/LOADING状态机。

### 【状态映射】

  状态ID      状态      动画要求
  ------------ --------- --------------------------------------------
  IDLE         待机      对应朝向待机动画
  MOVE         移动      对应8方向动画
  INTERACT     交互      交互动作；未配置时播放待机动画
  LOCKED       受限      待机或指定受限动作
  LOADING     加载      不显示可操作角色或加载占位

### 【动作编号】（关联第3章3.7）

  动作ID    动作名称   类型
  --------- ---------- ----------
  ACT_001   挥手       动作
  ACT_002   点头       动作
  ACT_003   开心       表情动作
  ACT_004   疑问       表情动作

### 【要求】

-   朝向动画采用8方向配置（第3章3.5），命名示例 `CHR_001_MOVE_NE_01`。
-   缺失方向动画需明确缺失方向与备用方案，不由程序猜测。
-   动画状态由客户端播放，不作为服务端权威状态依据。

### 【验收标准】

1.  五个状态均按状态机规则切换并播放对应动画。
2.  四种动作资源均可用并正确广播（第3章3.7）。
3.  缺失动画可使用配置备用动画且不崩溃。

## 18.10 资源目录结构

**优先级：【MVP必须】**

### 【功能说明】

给出统一资源目录树，作为资源管理与构建输入。

### 【目录树】

``` text
client/assets/
  resources/
    characters/CHR_001/{model,animation,portrait,preview}/
    characters/CHR_002/...
    maps/MAP_MAIN_001/{scene,ground,props,collision,areas,spawn,entrances,camera,config}/
    levels/LV_ROOM_01/...
    levels/LV_ROOM_02/...
    levels/LV_ROOM_03/...
    levels/LV_ROOM_04/...
    levels/LV_ROOM_05/...
    levels/LV_HIDDEN_01/...
    mechanisms/MEC_*/
    effects/FX_*/
    ui/UI_*/
    audio/AUD_*/
  bundles/
    bundle-world/
    bundle-rooms-01-02/
    bundle-rooms-03-05/
    bundle-hidden-ending/
```

### 【Asset Bundle / 微信分包】

- 主包只放启动场景、登录/鉴权入口、最小主地图 UI、必要脚本和共享依赖。
- bundle-world：主地图场景、地面、基础装饰和主地图必需 UI。
- bundle-rooms-01-02：ROOM-01、ROOM-02 场景资源及机关/法则表现。
- bundle-rooms-03-05：ROOM-03、ROOM-04、ROOM-05 场景资源及机关/法则表现。
- bundle-hidden-ending：隐藏结局场景、专属机关、结局特效和音频。
- 上述 bundle 以 Cocos Creator Asset Bundle 管理；微信小游戏本地分包不得勾选远程包。脚本原则上放主包，资源 bundle 不得相互引用对方内部脚本。
- 微信小游戏主包平台上限为 4 MB，全部分包合计上限为 30 MB（以当前 Cocos Creator 3.8 文档说明为基线，提交审核前须再用微信开发者工具确认）。项目内部安全预算：主包不超过 3.2 MB，全部分包合计不超过 24 MB；这是项目预算，不是平台硬限制。
- 单包大小与分包加载策略必须根据构建产物实测，不得只按源文件体积估算。

### 【要求】

- 目录结构变更需同步更新 Asset Bundle、资源加载配置和资源清单。
- Bundle 名称不得使用 Cocos 内置名称 internal、resources、main、start-scene。
- 未纳入目录或 bundle 的资源不得被正式构建引用。
- 资源 bundle 的加载/卸载必须有失败回退、重复加载保护和版本校验。

### 【验收标准】

1.  资源按目录树正确组织。
2.  构建输入仅包含目录内合规资源。

## 18.11 图集与压缩规范

**优先级：【MVP必须】**

### 【功能说明】

定义纹理格式、图集打包与压缩比的统一规范。具体数值待技术美术确定。

### 【规范（Cocos Creator 3.8.8 / 微信小游戏基线）】

| 项目 | MVP 基线 | 说明 |
|---|---|---|
| 原始源图 | 透明资源优先 PNG；不含透明通道的大面积背景可用 JPG；WebP 仅在目标机型验证后采用 | 源文件保留可编辑版本，不直接覆盖源图 |
| GPU 纹理压缩 | 默认评估 ASTC 6x6；边缘/文字/细线质量不足时改用 ASTC 5x5 或 PNG 回退 | Cocos 3.8 文档给出 2D/UI 可使用 ASTC 5x5（较高画质）或 6x6（较低画质）的建议 |
| 兼容回退 | 对所有关键 UI、角色和机关图集保留 PNG 回退格式 | 微信小游戏支持 ASTC / ETC1 / ETC2 / PVR；开发者工具不支持 ASTC，必须真机验证 |
| 透明资源 | 透明贴图优先采用 ASTC RGBA 或 PNG 回退；禁止未经验证地将透明素材压成 RGB-only | 防止边缘黑边、透明丢失 |
| 图集拆分 | 按主地图、角色、单个房间、UI、法则特效拆分；禁止把全游戏资源打进单张图集 | 控制首包和单场景加载峰值 |
| 图集尺寸 | 初始项目上限 2048×2048；超出必须拆分或提交技术美术例外评审 | 项目初始约束，需以低端机真机内存/加载实测校准 |
| 合批 | 同材质、同图集资源优先合批；透明排序正确性优先于合批 | 不得为合批破坏遮挡和深度排序 |

### 【要求】

- Cocos Creator 3.8.8 微信小游戏压缩纹理能力以官方文档为准：<https://docs.cocos.com/creator/3.8/manual/zh/asset/compress-texture.html>。
- PNG/JPG/WebP 文件压缩主要减少下载体积，不等同于降低解码耗时或 GPU 内存；GPU 压缩纹理才用于降低纹理显存占用。
- 压缩预设必须同时输出通用 PNG/JPG 回退，不得只输出 ASTC；ASTC 在微信开发者工具中不可作为通过依据，必须使用真机检查。
- 2048×2048 是本项目首轮图集上限，不是微信或 Cocos 的平台硬限制；如果设备实测出现内存峰值、加载时长或画质问题，必须下调。
- 图集超限、缺少回退格式、Alpha 异常、错误引用必须在资源验收/构建检查中报警。

### 【验收标准】

1. 关键资源在 ASTC 真机路径与 PNG 回退路径均显示正确。
2. 开发者工具预览不依赖 ASTC 成功，真机验证覆盖至少一台 iOS 和一台 Android 微信设备。
3. 图集按场景拆分，超出项目上限时构建检查失败。
4. 记录构建包体、首次加载耗时、场景切换耗时和纹理内存峰值。

## 18.13 帧率和内存目标

1.  20人同实例压测人数统计准确。
