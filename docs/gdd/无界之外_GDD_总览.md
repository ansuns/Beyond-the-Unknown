## 2. 全局规则（G-001 ~ G-017）

以下规则为全文档最高优先级约束，各章节不得与之冲突。

  编号    规则         当前结论
  ------- ------------ ------------------------------------------------------------
  G-001   多人共享     同一主地图中存在其他真实在线玩家
  G-002   个人独立     每名玩家任务和关卡进度独立
  G-003   随时进出     玩家可进入和离开，离开后保存个人进度
  G-004   角色公平     12 个预设角色能力一致
  G-005   角色差异     仅外观、动作、特效存在差异
  G-006   地图视角     2D 斜 45 度
  G-007   首期内容     1 个世界、5 个探索房间、3 条法则（回声、注视、逆流）
  G-008   法则组合     首期 3 组预设组合
  G-009   隐藏内容     首期 1 个隐藏结局
  G-010   单局时间     30–90 秒为目标
  G-011   多人容量     20 人是目标测试人数，不是最终硬上限
  G-012   排行榜       探索榜、通关榜、收藏榜
  G-013   赛季         周榜和月赛季
  G-014   积分公平     广告和付费不得直接增加排行榜积分
  G-015   社交范围     首期以预设动作和表情为主
  G-016   广告         首期预留接口，可暂不开启
  G-017   世界档案     【MVP必须】永久记录全服首次发现玩家、UTC时间、地点和相关法则；仅荣誉展示，不加排行榜积分

## 4. GDD 文档统一规范

### 4.1 文档头部

每章必须包含：文档版本号、章节名称、日期、变更日志、Open Questions（待定问题）、适用岗位、章节状态、优先级标记。V0.2起，跨章节冲突以本总览全局规则及各章V0.2修订条款为准。V0.2起，跨章节冲突以本总览全局规则和各章明确标注的V0.2修订条款为准。

### 4.2 系统描述格式

每个机制统一使用以下子标题：

1.  【触发条件】
2.  【玩家输入】
3.  【计算/规则】
4.  【反馈（动画、音效、UI、屏幕表现）】
5.  【边界与例外】

并配套【功能说明】与【验收标准】。

### 4.3 功能优先级

所有功能必须标记：

-   【MVP必须】：首版上线前必须完成并通过验收。
-   【可选扩展】：首版可以不实现，不影响核心流程。
-   【不在本期范围】：本期不设计、不开发、不纳入验收。

### 4.4 验收标准

每个系统结束后必须有验收标准，使用可测试、可判断的描述，不能只写体验感受。例如：

-   两名玩家进入同一关卡入口后，生成两个不同的关卡运行 ID。
-   玩家 A 操作机关后，玩家 B 的机关状态不发生变化。
-   玩家断线重连后，个人进度与断线前保存状态一致。

## 5. 实际开发优先级（按依赖关系）

18 章是文档结构，不代表开发顺序。实际建议按依赖关系推进：

  阶段       优先开发内容                       目标
  ---------- ---------------------------------- ------------------------------
  第一阶段   角色、地图、移动、多人同步           建立可运行的共享世界
  第二阶段   关卡、机关、世界法则                 验证核心探索玩法
  第三阶段   法则组合、发现、收藏、进度           形成完整玩法闭环
  第四阶段   排行榜、奖励、成就                   建立长期目标
  第五阶段   UI 完善、性能优化、测试             达到上线标准
  后续阶段   社交扩展、广告、宠物、装扮           持续运营和商业化
