# 第2章 核心玩法循环

## 2.1 核心流程定义

**优先级：【MVP必须】**

### 2.1.1 玩家完整流程

``` mermaid
flowchart TD
    A["启动微信小游戏"] --> B["微信登录"]
    B --> C{"是否已有角色"}
    C -->|否| D["选择预设角色"]
    C -->|是| E["读取玩家数据"]
    D --> F["进入共享主地图"]
    E --> F
    F --> G["移动与探索"]
    G --> H{"选择探索入口"}
    H -->|否| G
    H -->|是| I["进入个人探索关卡"]
    I --> J["使用世界法则"]
    J --> K{"是否满足完成条件"}
    K -->|否| J
    K -->|是| L["关卡结算"]
    L --> M["保存积分、发现与收藏"]
    M --> N["返回主地图"]
    N --> G
```

### 2.1.2 流程规则

  流程节点     执行内容               数据变化
  ------------ ---------------------- --------------------
  启动游戏     初始化客户端资源       无
  微信登录     验证登录凭证           获取玩家账号
  角色选择     选择预设角色           保存角色ID
  进入主地图   分配地图实例           创建地图在线状态
  移动探索     移动角色、触发交互     更新位置和必要状态
  进入关卡     创建个人关卡实例       创建关卡运行记录
  使用法则     执行法则效果           更新个人关卡状态
  完成关卡     服务端验证完成条件     生成结算记录
  获得奖励     写入积分和收藏         更新个人数据
  返回主地图   销毁个人关卡运行状态   保留已结算数据

**验收标准：**

-   从启动游戏到进入主地图，必须完成登录和角色数据初始化。
-   玩家能够完成一次完整探索关卡并返回主地图。
-   关卡结算后重新登录，已获得积分和收藏仍然存在。
-   玩家未完成关卡直接退出，不得生成通关积分。

## 2.2 登录与玩家初始化

**优先级：【MVP必须】**

### 【触发条件】

玩家首次启动游戏，或登录状态失效后重新启动游戏。

### 【玩家输入】

-   玩家点击游戏启动入口。
-   微信客户端提供登录凭证。
-   玩家根据界面提示完成必要授权操作。

### 【计算/规则】

1.  客户端调用微信登录接口获取临时登录凭证。
2.  客户端将凭证发送至游戏服务端。
3.  服务端向微信服务端验证凭证。
4.  服务端获取并验证玩家身份。
5.  根据身份查询玩家账号：
    -   已存在：读取玩家数据。
    -   不存在：创建玩家账号。
6.  读取玩家角色、进度、收藏、积分及奖励数据。
7.  返回玩家初始化数据。
8.  客户端根据返回结果进入角色选择界面或主地图。

**初始化数据字段：**

  字段               类型          说明
  ------------------ ------------- ----------------------
  player_id          string        游戏内部玩家ID
  character_id       string/null   当前角色ID
  is_new_player      boolean       是否首次进入
  player_level       integer       玩家等级；若首版启用
  progress_version   integer       玩家进度版本
  server_time        integer       服务端时间戳

注：玩家等级若没有实际玩法用途，首版不单独开发等级系统。

### 【反馈】

  状态               UI反馈
  ------------------ ------------------------------
  登录中             显示登录加载界面
  登录成功           显示角色选择或主地图加载界面
  登录失败           显示失败提示和重试按钮
  网络异常           显示网络异常提示
  账号数据读取失败   显示数据加载失败提示

### 【边界与例外】

-   微信登录凭证不得作为永久登录凭证保存。
-   玩家身份验证必须在服务端完成。
-   客户端不得自行指定或修改玩家内部ID。
-   重复登录请求不得重复创建玩家账号。
-   服务端暂时不可用时，不允许客户端进入正式游戏状态。
-   登录失败不允许生成新玩家数据。

### 【验收标准】

1.  新玩家登录后，数据库只创建一条玩家账号记录。
2.  老玩家登录后，读取原有角色和游戏进度。
3.  连续发送两次相同初始化请求，不产生重复账号。
4.  使用无效登录凭证，服务端拒绝登录。
5.  断网情况下，客户端显示异常提示，不进入主地图。

## 2.3 角色选择

**优先级：【MVP必须】**

### 【触发条件】

-   玩家首次登录，尚未选择角色。
-   玩家当前角色数据异常，需要重新选择。
-   玩家通过允许的角色更换入口主动更换角色（若首版开放该入口）。

### 【玩家输入】

-   点击角色列表中的角色。
-   点击确认按钮。

### 【计算/规则】

1.  服务端提供可选择角色列表。
2.  客户端展示12个预设角色。
3.  每个角色拥有唯一 `character_id`。
4.  玩家选择角色后，客户端发送角色ID。
5.  服务端检查角色ID是否存在、角色是否开放、玩家是否满足选择条件。
6.  验证成功后保存当前角色ID。
7.  返回选择结果。

**角色数据配置：**

  字段               类型     说明
  ------------------ -------- ----------------
  character_id       string   角色唯一ID
  character_name     string   角色名称
  model_id           string   角色模型资源ID
  portrait_id        string   角色头像资源ID
  animation_set_id   string   动画资源组ID
  unlock_condition   string   解锁条件

**角色能力规则：** - 12个预设角色的移动速度一致。 -
12个预设角色的碰撞体积一致。 - 12个预设角色的探索能力一致。 -
角色外观不影响机关判定。 - 角色动作和特效不影响排行榜积分。

### 【反馈】

-   角色列表显示角色立绘。
-   点击角色后，显示角色模型预览。
-   确认成功后，播放角色确认动作。
-   保存成功后进入主地图加载流程。

### 【边界与例外】

-   客户端提交不存在的角色ID时，服务端拒绝。
-   玩家重复点击确认时，只处理一次有效请求。
-   网络失败时，不修改当前角色。
-   角色模型资源加载失败时，使用默认占位模型，不阻塞账号数据保存。
-   首版是否允许随时更换角色，暂按允许设计；若更换，不能重置玩家进度。

### 【验收标准】

1.  新玩家可以从12个角色中选择一个。
2.  选择完成后重新登录，角色选择保持不变。
3.  使用不存在的角色ID提交，服务端拒绝。
4.  更换角色前后的关卡进度、积分、收藏保持一致。
5.  不同角色使用相同移动速度和碰撞体积配置。

## 2.4 进入共享主地图

**优先级：【MVP必须】**

### 【触发条件】

玩家登录成功且拥有有效角色数据。

### 【玩家输入】

玩家点击进入游戏按钮，或在登录后由客户端自动执行进入流程。

### 【计算/规则】

1.  客户端请求可进入的主地图实例。
2.  服务端检查玩家是否已有有效在线实例。
3.  有效实例存在时，允许玩家重新连接原实例。
4.  不存在有效实例时，查询目标地图当前实例人数。
5.  选择未满员且状态正常的实例；不存在符合条件的实例时创建新实例。
6.  服务端将玩家加入实例。
7.  服务端返回地图资源ID、实例ID、出生位置和附近玩家数据。
8.  客户端加载地图资源。
9.  地图加载完成后显示玩家角色。

**地图实例配置：**

  参数                         配置值 说明
  ---------------- ------------------ ------------------
  初始地图数量                      1 MVP
  单实例目标人数                   20 压力测试目标
  实例人数上限             待压测确定 服务端配置
  玩家出生点             固定出生区域 根据地图配置
  地图实例ID                     唯一 服务端生成
  实例状态           OPEN/FULL/CLOSED 开放、满员、关闭

### 【反馈】

  状态           客户端表现
  -------------- ------------------------
  请求实例       显示加载动画
  分配实例成功   加载地图资源
  地图加载完成   显示玩家角色和周围玩家
  实例满员       自动尝试其他实例
  服务端异常     显示进入失败提示

### 【边界与例外】

-   同一玩家同一时间只能拥有一个有效主地图在线状态。
-   已满员实例不得继续接收新玩家。
-   实例关闭时，服务端必须阻止新玩家加入。
-   玩家重复点击进入，不得生成多个在线角色。
-   玩家断线后，保留一定时间的重连资格；具体时间由网络系统章节配置。
-   实例创建失败时，不得返回无效实例ID。

### 【验收标准】

1.  20名测试玩家可以进入同一实例（以压测通过为前提）。
2.  实例达到人数上限后，新玩家进入其他实例。
3.  同一账号重复发送进入请求，不产生重复在线角色。
4.  关闭状态实例拒绝新玩家进入。
5.  玩家进入成功后，客户端显示正确地图和出生位置。

## 2.5 主地图移动与探索

**优先级：【MVP必须】**

### 【触发条件】

玩家已成功进入主地图，且角色处于可移动状态。

### 【玩家输入】

首版暂定采用虚拟摇杆： - 玩家按住摇杆并拖动，控制移动方向。 -
玩家松开摇杆，停止移动。

### 【计算/规则】

**移动参数暂定：**

  参数         初始值 单位
  ---------- -------- --------------------
  移动速度        160 像素/秒
  加速度            0 暂不启用
  减速度            0 暂不启用
  移动方式     八方向 方向输入归一化
  碰撞检测       开启 不允许穿越阻挡区域

上述数值为首轮原型配置，不代表最终上线数值。

设摇杆输入为 `D=(x,y)`，归一化方向为：

`D' = D / sqrt(x² + y²)`

移动位置：

`P_new = P_old + D' × V × Δt`

其中： - `P`：角色位置。 - `V`：移动速度。 - `Δt`：帧间隔时间。

**移动限制：** 1. 角色只能在地图可行走区域移动。 2.
角色不能穿越阻挡碰撞体。 3. 角色不能通过客户端修改服务端确认位置。 4.
服务端定期验证移动距离和速度。 5. 角色进入不可移动状态时，移动输入无效。

### 【反馈】

  状态           动画/UI
  -------------- --------------------------
  静止           播放待机动画
  移动           播放对应方向移动动画
  碰撞阻挡       角色停止或沿可行方向滑动
  离开可行区域   角色无法继续向该区域移动

角色朝向根据移动方向切换。

### 【边界与例外】

-   摇杆输入为零时，角色停止移动。
-   摇杆输入长度大于1时，必须归一化。
-   服务端发现移动速度异常时，拒绝异常位置更新。
-   网络延迟时，客户端可以进行本地移动预测，但服务端位置为最终有效位置。
-   玩家进入关卡、结算或退出地图时，停止主地图移动。

### 【验收标准】

1.  玩家能够使用摇杆完成八方向移动。
2.  同一角色不同方向移动速度一致。
3.  角色不能穿越地图阻挡区域。
4.  输入超出最大摇杆范围时，移动速度不增加。
5.  客户端伪造超速位置时，服务端拒绝异常位置。

## 2.6 探索入口与关卡启动

**优先级：【MVP必须】**

### 【触发条件】

玩家进入探索入口的有效交互范围。

### 【玩家输入】

-   靠近探索入口。
-   点击屏幕交互按钮。
-   确认进入关卡。

### 【计算/规则】

1.  客户端检测玩家与探索入口的距离。
2.  距离小于入口交互半径时，显示交互按钮。
3.  玩家点击交互按钮。
4.  客户端向服务端提交关卡进入请求。
5.  服务端验证玩家在线状态、关卡ID、关卡开放状态和进入条件。
6.  验证通过后创建个人关卡运行实例。
7.  服务端返回关卡初始化数据。
8.  客户端加载关卡场景。
9.  关卡初始化完成后进入游戏状态。

**入口配置：**

  字段                 类型      说明
  -------------------- --------- ------------
  entrance_id          string    入口唯一ID
  level_id             string    对应关卡ID
  position             vector2   入口位置
  interaction_radius   float     交互半径
  unlock_condition     string    开放条件

### 【反馈】

-   进入交互范围：显示入口名称和交互按钮。
-   点击交互按钮：显示关卡信息。
-   确认进入：播放进入场景过渡动画。
-   加载完成：显示关卡目标和操作提示。

### 【边界与例外】

-   不满足解锁条件时，不允许进入。
-   玩家重复提交进入请求，只允许创建一个有效关卡实例。
-   关卡资源加载失败时，返回主地图。
-   关卡关闭或维护时，入口显示不可进入状态。
-   其他玩家进入同一入口，不改变当前玩家的关卡状态。

### 【验收标准】

1.  玩家进入交互半径后出现交互按钮。
2.  玩家离开交互半径后按钮隐藏。
3.  满足条件的玩家可以进入关卡。
4.  不满足条件的玩家无法进入关卡。
5.  两名玩家同时进入同一个入口，各自生成独立关卡状态。

## 2.7 法则使用与关卡操作

**优先级：【MVP必须】**

### 【触发条件】

玩家处于已启动的个人探索关卡中，且拥有可使用的法则。

### 【玩家输入】

-   点击法则按钮。
-   选择目标对象或目标区域。
-   确认使用。

### 【计算/规则】

1.  客户端提交法则ID和目标对象ID。
2.  服务端验证玩家关卡状态。
3.  验证玩家是否拥有该法则。
4.  验证法则是否允许在当前关卡使用。
5.  验证目标对象是否有效。
6.  计算法则效果。
7.  更新该玩家个人关卡状态。
8.  返回执行结果。

**首批法则：**

  法则   输入方式                 核心效果
  ------ ------------------------ --------------------------------------
  回声   点击法则按钮             产生脉冲，显示隐藏物体或激活对应机关
  注视   点击法则按钮并指定目标   使指定目标在持续注视期间保持存在
  逆流   点击法则按钮并指定目标   反转指定对象或能量流动方向

具体作用范围、持续时间、冷却时间在第7章（世界法则系统）定义；机关适配表在第9章（交互与机关系统）定义。

### 【反馈】

-   法则按钮进入触发状态。
-   播放对应法则特效。
-   显示目标对象状态变化。
-   操作失败时显示明确失败原因。
-   冷却中的法则显示剩余冷却时间。

### 【边界与例外】

-   玩家没有对应法则时，服务端拒绝操作。
-   目标对象不存在时，操作失败。
-   法则不适用于目标对象时，不修改关卡状态。
-   玩家退出关卡后，不能继续提交法则操作。
-   同一操作请求重复提交，不得重复产生效果。
-   玩家A使用法则不得改变玩家B的个人关卡状态。

### 【验收标准】

1.  玩家可以使用已获得法则。
2.  未获得的法则无法触发。
3.  不适用的目标对象不会产生法则效果。
4.  重复提交同一请求不会重复激活机关。
5.  两名玩家分别使用法则时，个人机关状态互不影响。

## 2.8 关卡完成与结算

**优先级：【MVP必须】**

### 【触发条件】

玩家完成当前关卡配置的全部必要目标。

### 【玩家输入】

玩家完成最后一个必要机关或目标操作。

### 【计算/规则】

1.  玩家触发最后一个必要目标。
2.  服务端读取玩家当前关卡状态。
3.  服务端检查所有必要目标是否完成。
4.  满足条件时，将关卡状态设置为 `COMPLETED`。
5.  服务端生成唯一结算记录。
6.  计算通关积分。
7.  检查是否产生首次发现事件。
8.  检查是否获得收藏品。
9.  写入积分事件和奖励记录。
10. 返回最终结算数据。

**关卡状态：**

  状态        说明
  ----------- ------------------
  CREATED     已创建，尚未开始
  RUNNING     正在进行
  COMPLETED   已完成
  FAILED      已失败
  ABANDONED   玩家主动放弃

**结算数据：**

  字段               类型      说明
  ------------------ --------- --------------
  result_id          string    唯一结算ID
  player_id          string    玩家ID
  level_id           string    关卡ID
  completion_time    integer   通关耗时
  completion_score   integer   通关积分
  discoveries        array     本局发现内容
  collections        array     本局收藏内容
  result_status      string    结算状态

### 【反馈】

结算界面展示： - 关卡名称。 - 通关结果。 - 通关耗时。 - 本次获得积分。 -
新发现内容。 - 新增收藏内容。 - 返回主地图按钮。

### 【边界与例外】

-   客户端不得直接提交最终积分。
-   服务端未验证完成条件时，不允许结算成功。
-   重复结算请求不得重复增加积分。
-   结算写入失败时，保留待处理状态，允许服务端重试。
-   玩家在结算完成前断线，不得直接认定通关成功。
-   玩家已经完成的关卡再次进入时，按关卡配置处理重复通关奖励。

### 【验收标准】

1.  所有必要目标完成后才能通关。
2.  缺少任意必要目标时不能结算成功。
3.  客户端伪造积分时，服务端不采纳。
4.  重复发送结算请求只生成一份有效结算记录。
5.  结算完成后重新登录，积分和收藏记录保持一致。

## 2.9 返回主地图与进度恢复

**优先级：【MVP必须】**

### 【触发条件】

-   玩家点击返回主地图。
-   玩家完成关卡并点击返回。
-   玩家退出当前关卡。
-   客户端重新连接并请求恢复游戏状态。

### 【玩家输入】

-   点击返回按钮。
-   确认退出未完成关卡。
-   重新启动游戏或重新连接。

### 【计算/规则】

1.  客户端提交退出请求。
2.  服务端检查当前关卡状态。
3.  已完成关卡：保留全部结算数据。
4.  未完成关卡：首期不恢复机关/谜题临时状态；退出时仍必须保存退出前已确认的永久发现、收藏、奖励、积分、角色与已完成关卡记录。
5.  关闭当前个人关卡运行实例。
6.  将玩家放回主地图。
7.  如果玩家重新登录，服务端读取已保存进度。
8.  客户端根据返回数据恢复玩家状态。

**首版进度保存规则：**

  数据                 保存方式
  -------------------- ----------------------------------------
  当前角色             永久保存
  已完成关卡           永久保存
  已获得法则           永久保存
  已发现内容           永久保存
  已获得收藏           永久保存
  已获得积分           永久保存
  未完成关卡临时状态   首版不恢复；已确认永久进度照常保存
  当前地图坐标         可按需要保存，异常退出时使用安全出生点

### 【反馈】

-   退出时显示确认界面。
-   返回主地图时播放场景切换动画。
-   恢复数据时显示加载状态。
-   恢复成功后显示玩家角色和地图状态。

### 【边界与例外】

-   玩家退出未完成关卡，不产生通关积分。
-   已完成关卡的积分和收藏不能因退出而回滚。
-   网络断开时，服务端保留已提交的数据。
-   客户端本地缓存不得覆盖服务端已确认数据。
-   服务器无法恢复未提交的操作时，不得将其计入发现、收藏或排行榜。
-   玩家重新进入时，如果原地图实例已关闭，应重新分配地图实例。

### 【验收标准】

1.  玩家完成关卡后退出，积分与收藏保留。
2.  玩家未完成关卡退出，不获得通关积分。
3.  玩家重新登录后，角色和已保存进度正确恢复。
4.  玩家断线重连后，不产生重复奖励。
5.  原地图实例关闭时，玩家可以进入新的有效实例。
