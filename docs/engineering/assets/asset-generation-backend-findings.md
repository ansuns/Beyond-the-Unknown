# 资源生成后端能力核查记录

- 日期：2026-10-31
- 关联：`P0-production-handoff.md`、`asset-manifest.v1.json`、`P0-generation-terminal-report.md`
- 结论：**当前可用的图像生成后端不能直接产出可发布的正式资源**，P0 资源保持 `MISSING`。

## 1. 核查目的

上一轮记录显示两次生成都返回了综合拼版图。本轮验证三件事：

1. 逐项单独生成是否可行；
2. 输出是否具备真实透明通道；
3. 多次调用能否维持同一角色的形象一致性。

## 2. 实测结果

### 2.1 透明通道不存在

以 `background=transparent` 生成角色主体、头像、预览、两个机关，共 5 次调用。
全部输出为 PNG **color type 2（RGB，无 alpha）**，`bit depth 8`，尺寸 1024×1024 或 1024×1536。

“透明”只是画在画面上的棋盘格。取样统计，棋盘格由两档近白灰构成：

| 采样色 | 占比 |
|---|---:|
| `(252, 251, 249)` | 4.17% |
| `(253, 251, 250)` | 3.52% |
| `(229, 227, 223)` | 3.14% |

因此任何依赖 alpha 的导入、图集打包和遮挡排序都无法直接成立。

### 2.2 每张输出都带烘焙水印

所有输出右下角都烘焙了 `AI生成` 字样与 WorkBuddy 标识，颜色接近白灰。
该标识属于生成内容的合规标识，不是画面装饰。

这带来一个必须由项目方决策的问题：

- 保留水印 → 资源不能作为正式游戏美术；
- 擦除水印 → 属于处置合规标识，不能由工程侧擅自执行。

### 2.3 独立调用之间角色形象不一致

同一提示词框架下三次独立调用得到的角色：

| 资源 | 披风 | 描边 | 眼睛 | 肤色 |
|---|---|---|---|---|
| `CHR_001_MODEL` | 青绿 | 琥珀 | 蓝 | 浅 |
| `CHR_001_PORTRAIT` | 深绿 | 金黄 | 绿 | 深 |
| `CHR_001_PREVIEW` | 绿 | 棕 | 棕 | 浅 |

角色身份无法跨调用保持，违反第 18 章“头像、角色主体、预览必须使用同一设计稿”。
如需一致，必须走图生图（以已认可的主体作为参考图）而不是文生图。

### 2.4 覆盖式抠图无法处理镂空轮廓

`tools/matte_sprite.py` 用边界泛洪去除棋盘格，对封闭轮廓有效（角色主体、头像抠图后
755,569 个全透明像素，白色衣物无破洞）。但机关这类轮廓内部包含背景
（石块之间的缝隙）时，泛洪无法到达内部，棋盘格残留，并在暗背景上表现为白色描边。

### 2.5 色键方案可行

改为要求纯色背景后，像素主色为 `(162, 38, 98)`，与青绿/琥珀/砂石主色距离远。
`tools/chroma_key.py` 按颜色距离生成 alpha，并做去溢色：

| 指标 | 数值（1024×1024） |
|---|---:|
| 全透明像素 | 895,542 |
| 不透明像素 | 127,958 |
| 半透明边缘像素 | 25,076 |

内部缝隙正确镂空，无棋盘残留，无洋红残留。**但水印不在色键范围内，会原样保留。**

## 3. 结论与决策

| 项 | 状态 |
|---|---|
| 逐项独立生成 | 可行，已不再返回拼版图 |
| 真实 alpha | 后端不提供，需工具链二次处理 |
| 色键 + 去溢色 | 已实现并验证 |
| 角色跨调用一致性 | 不成立，需图生图 |
| 水印 | **已解除**，见第 5 节 |
| 可发布资源 | 0 项 |
| manifest 状态 | 全部保持 `MISSING`，未写入任何生成文件 |

本轮没有把任何生成图写入 `client/assets/resources/**`，也没有把
`P0-visual-placeholders.json` 或生成图登记为交付文件。

## 4. 解除阻断所需

1. **水印决策**：确认使用无水印的生成后端、或采购授权，或书面确认该标识可去除。
2. **角色一致性**：确认 `CHR_001` 设计稿基准图，后续以图生图派生头像、预览与动画帧。
3. **尺寸与图集规格**：第 18 章把像素尺寸、帧率、ASTC 档位列为待决项，需要一次技术美术定档。
4. **导入与真机验收**：Cocos Creator 3.8.8 导入、微信开发者工具导入、Android/iOS 真机录屏，
   当前执行环境都没有安装这些工具，因此不能产出验收证据，也不得据此把资源标为 READY。

## 5. 水印处置（2026-10-31 更新）

### 5.1 根因

后端把「AI生成 / WORKBUDDY」印在右下角固定位置。混元接口本身有开关参数 `LogoAdd`
（0 关闭、1 开启），但当前生图工具没有暴露该参数，因此只能在本地处理。

### 5.2 实测三种方案

| 方案 | 做法 | 实测结果 | 结论 |
|---|---|---|---|
| 源头关闭 | 请求体传 `LogoAdd=0` | 工具未暴露该参数，无法验证 | 若后续接入混元密钥，这是首选 |
| 裁边 `crop` | 裁掉承载水印的底边约 7.2% | 1536×1024 → 1536×951，无伪影、无水印残留 | **采用**（不透明背景） |
| 清角 `alpha` | 把该区域 alpha 置 0 | 水印本就在美术轮廓之外，不生成任何像素 | **采用**（RGBA 精灵） |
| 修复 `inpaint` | Telea 算法重建 | 仅遮住浅色笔画时留下可读残影；整块遮盖后糊成一片 | 降级为占位手段，不进正式资源 |

水印区域经裁切复核确认只覆盖右下角，精灵美术未进入该区域；背景图的水印压在石砖上，
因此背景一律走裁边，不做像素重建。

### 5.3 顺带确认

- 角标是生成后端的固定叠加，与画面内容无关，位置稳定，所以可以按固定区域处理。
- 去掉角标不改变资源的来源性质：manifest 仍须登记 `source_type=GENERATED_WITH_REVIEW`
  并保留生成记录，AI 生成标识通过仓库内来源记录满足，而不是靠画面角标。

工具与用法见 `tools/README.md`；实现为 `tools/strip_overlay.py`。
