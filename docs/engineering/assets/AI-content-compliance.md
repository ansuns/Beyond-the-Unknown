# AI 生成内容：合规状态与处置规则

- 日期：2026-10-31
- 关联：`asset-generation-backend-findings.md`、`tools/README.md`、`asset-manifest.v1.json`
- 状态：**未核实完成**。在本文第 4 节各项确认之前，任何生成资源不得标记为 `READY`。

## 1. 本文要解决的问题

工程侧已经能稳定产出可用的独立资源文件（真实 alpha、正确命名、进正确目录），也能去掉生成后端烙在
右下角的「AI生成 / WORKBUDDY」角标。但**「能去掉」不等于「可以去掉」**，更不等于「已获授权」。
本文把不确定的部分显式记录下来，避免把技术处理当成合规结论。

## 2. 已知事实

| 项 | 状态 | 依据 |
|---|---|---|
| 角标来源 | 生成后端在输出上叠加的固定角标，非画面内容 | 复核多张输出，位置固定 |
| 关闭方式 | 混元接口参数 `LogoAdd=0` | 外部技术文章；**本仓库未验证** |
| 本仓库生图工具是否暴露该参数 | 否 | `ImageGen` 工具参数表无 `LogoAdd` |
| 现有处置方式 | 精灵清 alpha 角、背景裁边 | `tools/strip_overlay.py`，23 项测试覆盖 |
| 处理后是否等同合规 | **否** | 见第 3 节 |

## 3. 明确不能做的推论

以下四条都是**错误**推论，本文明确否定：

1. ❌「去掉了角标，所以资源可以商用」——角标是平台的展示层，不是授权凭证。
2. ❌「仓库里记了 source_reference 和生成记录，所以已获授权」——记录证明来源，不证明授权。
3. ❌「角标可以关，所以任何来源的图都能同样处理」——不同来源授权条款不同，必须分别判断。
4. ❌「工具测试通过，所以资源可以标 READY」——工具正确性与授权、验收是三件事。

## 4. 待项目方确认的事项

在下列事项全部确认前，生成资源保持 `IN_PROGRESS`，不得 `READY`：

| 编号 | 待确认 | 影响 |
|---|---|---|
| C-1 | 生成服务的使用条款是否允许关闭标识、是否允许商用与再分发 | 决定能否使用这批资源 |
| C-2 | 该服务条款是否要求保留可识别的来源信息或内容标识 | 若要求保留，则本地去角标的做法不适用 |
| C-3 | 本项目是否落在适用的 AI 生成内容标识要求范围内（发布渠道、地区） | 决定是否需要显式标识 |
| C-4 | 若需要标识，采用何种形式（应用内说明、启动页声明、元数据） | 影响客户端与发布流程 |

## 5. 当前仓库的实际做法

1. **不标记 READY**：112 条中 0 条 READY；已交付的 3 条为 `IN_PROGRESS`。
2. **参考图保留角标**：`assets/reference/CHR_001_base.png` 未做处理，作为生成来源的可见记录。
3. **provenance 记录来源而非授权**：`source_type=GENERATED_WITH_REVIEW` + `source_reference`，
   `license` 字段明确写为待核实，不写「自有版权」之类未经确认的结论。
4. **工具不承诺合规**：`tools/README.md` 与工具 docstring 均写明，去角标不改变资源性质。
5. **分区处理**：若 C-2 结论要求保留标识，则仅允许「未处理、带角标」的版本入库，现有三件资源需回退重制。
