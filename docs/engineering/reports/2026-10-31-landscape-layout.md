# 横屏布局整改与真机尺寸验收（2026-10-31）

## 1. 先回答"全是黑的"

截图里那块黑不是游戏画布，是微信开发者工具自己的面板底色。逐像素采样可以区分：

| 区域 | 采样点 | RGB | 是什么 |
|---|---|---|---|
| 大面积"黑" | (300, 700) | `(46, 47, 48)` | 开发者工具面板背景 |
| 游戏画布 | (300, 150) | `(11, 19, 33)` | 客户端 `Background` 的 `Color(10, 18, 32)` |
| 设备边框 | (16, 250) | `(59, 60, 61)` | 模拟器机身 |

画布实际占 `x 17–589`、`y 136–399`，即 **572 × 263**，宽高比 **2.17**，正好是 iPhone 14 横屏的 844 × 390。也就是说画面是**铺满整个横屏手机**的，没有黑边、没有留白。下面那一大片是开发者工具窗口很长而模拟器只占顶部时留下的空面板。

所以"全是黑的"这个判断基于的是一张会误导人的截图；但截图里确实有真问题，见下一节。

## 2. 截图里真正的问题

同一张截图放大后能看到三处碰撞：

1. 引擎性能面板（Framerate / Draw call / …）压在"登录并进入世界"按钮上；
2. "法则：尚未读取"压在房间美术上；
3. 房间里的"回声·显形 / 靠近出口并交互"两个按钮落在房间中央，正好盖住角色。

原因不是压缩，是布局：**所有偏移量都是按 960×640 预览写死的常量**。

```ts
// 整改前
this.createButton("ProgressButton", "我的进度", -size.width / 2 + 72, size.height / 2 - 145, …);
worldTransform.setContentSize(min(size.width - 48, 760), min(size.height - 250, 420));
```

手机横屏的可见高度是 **443**（960 固定宽度策略下，844×390 换算成 960×443），于是：

- 世界区高度 = `443 - 250 = 193`，只占屏幕 **43%**；
- 底排按钮 `-443/2 + 62`、法则 `-443/2 + 126`，全部挤进世界区里；
- 房间按钮 `-size.height / 2 + 112` 在 232 高的世界区里变成 **+(-4)**，即正中间。

另外 `calculatePrototypeRoomScale` 又扣了一次 240：

```ts
const availableHeight = Math.max(120, size.height - 240);  // size 已经是世界区，不是窗口
```

240 的预留是给窗口级 chrome 的，而世界区已经扣过一遍，等于**重复扣除**，房间被压到视口的五分之一。

## 3. 整改

### 3.1 外壳改为按可用高度的两段堆叠

`computeShellLayout(size)` 从上下边缘各推一遍，得到 title / status / nav / progress / world / rules / buttons 的位置，并在 `height < 560` 时整体切紧凑档：

| 项 | 常规（h≥560） | 紧凑（h<560） |
|---|---:|---:|
| 标题字号 | 30 | 21 |
| 导航按钮高 | 44 | 30 |
| 底排按钮高 | 54 | 40 |
| 底部提示行 | 显示 | 不显示 |
| 世界区占比（844×390） | — | **60%**（原 43%） |

### 3.2 房间操作行同样从底边堆叠

`roomControlLayout(size)` 给出 `primaryY` / `actionY`，两行从世界区底边往上排，紧凑档 32 高、间隔 6。

### 3.3 房间缩放不再重复扣预留

`availableHeight = max(80, size.height - 24)`，只留美术四周 24 px 边距。

原先锁定 18 / 8 的测试断言的正是重复扣除的结果，改成断言契约本身（装得下、不超过上限 40）。

### 3.4 关掉引擎性能面板

`profiler.hideStats()`。这块面板就是压住登录按钮的东西，且它只在调试构建里出现，正式包不该带。

## 4. 验收（844×390 即开发者工具真实视口）

`tools/verify-landscape.mjs` 新增 844×390，向引擎查询每个控件世界矩形后与可见区比较：

| 比例 | 画布 | 可见区 | 控件 | 越界 |
|---|---:|---:|---:|---|
| 16:9 | 1280×720 | 960×540 | 16 | 0 |
| 18:9 | 1440×720 | 960×480 | 16 | 0 |
| 19.5:9 | 1560×720 | 960×443 | 16 | 0 |
| 20:9 | 1600×720 | 960×432 | 16 | 0 |
| 844×390 | 844×390 | 960×444 | 16 | 0 |

截图在 `build/verify/landscape/`。

`tools/drive-screenshot.mjs` 之前把 `#GameDiv` 当成自适应容器，但 web 模板把它写死 1280×960，所以"手机尺寸截图"其实是从 1280 宽画布上裁的一块。现在会在启动前改容器尺寸，手机尺寸的截图才可信。

### 4.1 房间链路端到端

844×390 下驱动真实构建：登录 → 世界 → 进房 → 点隐藏物 → 走近 → 回声 → **"回声扩散：隐藏的符号显现了"**，隐藏符号画在角色旁边（`build/verify/phone/05-echo-cast.png`）。

### 4.2 顺带修掉的两个真问题

1. **回声失败提示**：`RULE_ECHO` 半径 2.0，出生点 x=1，隐藏物 x=5，距离 4.0，服务端拒绝是**对的**（防止隔着整间房显形）。但状态行直接打印了 API 原文 `Rule target is invalid or outside the configured scope`，看起来像 bug。现在 422 会显示"回声范围外：先走近隐藏的符号再施放"。
2. **截图脚本点空**：原来点的是写死的页面像素 `(597, 410)`，那是给 1280 宽画布算的，在 844×390 下根本没点进房间。现在直接点 `HiddenObject` 节点中心。
