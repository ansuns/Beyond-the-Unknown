### S2 服务端完成 —— 待开始

优先级最高的是把“已实现未验证”变成“已验证”，且不依赖数据库：

1. 把结算评分、三榜排名、赛季归档抽成纯函数，补单测（当前只有集成覆盖）。
2. 机关状态机与组合技判定的边界用例（重复触发、跨房间、超时）。
3. 断线宽限 `map_reconnect_grace_seconds` 的过期语义。
4. `task_outbox` 重试与幂等键冲突的行为。

出口条件：17 项集成测试在真实 PostgreSQL + Redis 下全绿；纯函数单测覆盖上述四项。

### S3 Cocos 客户端 —— 待开始（受 B-2 阻塞）

1. 场景与组件真实挂接：只有 TS 类不算完成，必须在 `Boot.scene` 上可见。
2. 主角移动、机关交互、技能操作、房间切换、多玩家显示。
3. 断线重连的可视状态。
4. 结算与 UI 状态机。

出口条件：Cocos Creator 3.8.8 打开工程无资源丢失/UUID 冲突，构建产物可在预览中跑通 ROOM-01。

### S4 美术与音效 —— 受 B-5 / B-6 阻塞

按 `P0-production-handoff.md` §10 的验收顺序推进。当前必须先把两件事定下来：

1. 生成资源的合规水印如何处置（保留 / 换后端 / 采购授权）。
2. `CHR_001` 基准设计图，其后头像、预览、动画一律图生图派生。

出口条件：P0 37 项逐项具备独立文件、授权证据、验收证据，`validate:release-assets` 通过。

### S5 端到端联调 —— 待开始

按用户定义的 12 项验收逐条执行，每条都要有可复现记录：
进入游戏、进退房间、移动、机关交互、规则与组合技、五个常规房间、隐藏路线、隐藏结局、结算、进度存档、断线重连、多玩家同步。

出口条件：12 项全部有录屏或测试记录，且失败项不得以“历史已通过”代替。

### S6 微信小游戏交付 —— 待开始（受 B-3 阻塞）

构建、导入、AppID、域名白名单、登录会话、隐私合规、包体积、首屏加载、真机测试、发布清单。
`AppSecret` 等凭据只进环境变量，不进仓库。

出口条件：Android 与 iOS 各一台真机完成安装、登录、进入房间、结算全流程。

## 2. 并行约束

- 同一文件同一时间只允许一个分支修改。
- 资源分支与代码分支互不阻塞，但改动 `asset-manifest.v1.json` 的分支必须串行。
- 任何 PR 需通过 `server-ci` 或 `client-ci` 后才能合并；失败必须修，不得绕过。
