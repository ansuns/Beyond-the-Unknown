## 14.0 本章范围

本章定义首期轻社交系统：玩家在地图内通过预设动作与表情进行非文字社交表达，以及对附近玩家的可见信息展示与社交反馈。

本章不定义文字聊天、好友、交易、公会、组队等复杂社交系统（见 14.6【不在本期范围】与第1章 1.4.3、全局规则 G-015）。

**设计基线：**

1.  首期社交以预设动作和表情为主，不支持自由文字（G-015）。
2.  所有社交表达不产生数值收益，不影响关卡完成、探索或排行榜积分（关联第13章 G-014）。
3.  动作与表情清单与第3章 3.7 对齐：ACT_001 挥手、ACT_002 点头、ACT_003 开心、ACT_004 疑问；可扩展其他预设动作，均须为非文字、无数值收益。
4.  动作/表情的广播范围与频率受第5章（多人共享系统）可见范围与联机频率限制约束。

## 14.1 预设动作与表情清单

**优先级：【MVP必须】**

### 【功能说明】

提供一组预设的、非文字的社交表达，供玩家在地图内快速传递情绪与意图，不产生任何数值收益。

### 【触发条件】

-   玩家位于可操作场景，角色未处于禁止动作状态（如第3章 3.4 的 LOCKED）。
-   玩家点击动作/表情按钮并选择一项。

### 【玩家输入】

-   打开动作/表情面板。
-   点击某一动作条目。

### 【计算/规则】

预设动作清单（与第3章 3.7 对齐）：

  动作ID    动作名称   类型       是否循环   数值收益
  --------- ---------- ---------- ---------- ----------
  ACT_001   挥手       动作       否         无
  ACT_002   点头       动作       否         无
  ACT_003   开心       表情动作   否         无
  ACT_004   疑问       表情动作   否         无

扩展规则：

1.  可经配置新增其他预设动作（如"欢呼""招手"等），新增动作必须同样为非文字、无数值收益。
2.  所有动作 ID 由服务端配置表下发，客户端不得自定义动作含义。
3.  动作不写入任何积分、收藏、任务或道具（关联第13章、第10章、第11章）。
4.  动作不得携带任意文本或脚本参数（防滥用，关联第3章 3.7）。

### 【反馈（动画、音效、UI、屏幕表现）】

-   动作面板以图标形式展示可用动作。
-   点击后角色播放对应动作动画。
-   动作播放完成后恢复待机或移动状态。

### 【边界与例外】

-   非法动作 ID 被服务端拒绝。
-   `LOCKED` 状态下默认禁止动作。
-   资源缺失时动作不播放但不得导致客户端崩溃。

### 【验收标准】

1.  玩家可触发 ACT_001~004 四种预设动作。
2.  动作不产生积分、进度或收藏变化。
3.  新增扩展动作仍满足非文字、无数值收益。
4.  非法动作 ID 被服务端拒绝。

## 14.2 玩家展示信息

**优先级：【MVP必须】**

### 【功能说明】

在地图内展示玩家自身及附近可见玩家的公开信息，帮助玩家识别彼此，但不暴露隐私数据。

### 【触发条件】

-   玩家进入地图并出现其他可见玩家（可见范围见第5章）。
-   玩家打开附近玩家列表或查看某玩家信息。

### 【玩家输入】

-   （可选）点击附近玩家头像查看简报。

### 【计算/规则】

可展示的公开信息：

  信息项       数据来源            说明
  ------------ ------------------ --------------------------------------------
  角色外观     第3章 角色系统     当前使用角色模型/配色
  角色名称     玩家资料           显示名（非敏感）
  称号         第12章 奖励成就    已获得称号，按展示优先级显示
  收藏数       第10章 收藏系统    收藏图鉴数量（可选展示）
  使用动作     第14章 动作系统    当前正在播放的预设动作/表情

规则：

1.  展示信息仅含公开字段，不含账号、联系方式等隐私。
2.  角色外观与称号展示受第3章、第12章配置约束。
3.  展示数据由服务端下发，客户端不做二次加工。
4.  未解锁称号/外观不得展示。

### 【反馈（动画、音效、UI、屏幕表现）】

-   附近玩家以头像或头顶标识展示。
-   点击头像弹出简报卡（角色外观、称号、收藏数）。
-   称号按第12章规则显示。

### 【边界与例外】

-   玩家资料未加载完成时显示占位，不显示空白卡。
-   已屏蔽/隐藏状态的玩家按第5章规则处理可见性。

### 【验收标准】

1.  附近可见玩家头像/标识正常展示。
2.  简报仅含公开信息。
3.  未解锁称号不展示。
4.  资料缺失时显示占位不崩溃。

## 14.3 动作触发与广播

**优先级：【MVP必须】**

### 【功能说明】

玩家触发动作后，由服务端校验并向同地图实例内的可见玩家广播动作事件。

### 【触发条件】

-   玩家选择并确认一个合法动作。
-   玩家处于允许动作的状态。

### 【玩家输入】

点击动作条目触发。

### 【计算/规则】

1.  客户端发送动作 ID 至服务端。
2.  服务端校验：动作 ID 是否开放、玩家是否在线、是否处于允许动作状态、是否超频（见 14.5）。
3.  校验通过后，服务端向该玩家所在地图实例内、符合第5章可见范围规则的玩家广播动作事件。
4.  接收客户端按动作 ID 播放对应角色动作。
5.  动作播放完成后恢复原状态。
6.  广播只发送动作 ID 与角色标识，不发送文本。

``` mermaid
sequenceDiagram
    participant P as 玩家A客户端
    participant S as 服务端
    participant O as 附近玩家客户端
    P->>S: 发送动作ID(ACT_xxx)
    S->>S: 校验动作/状态/频率
    S-->>O: 广播动作事件(角色ID, 动作ID)
    O->>O: 播放对应动作动画
```

### 【反馈（动画、音效、UI、屏幕表现）】

-   触发方立即本地播放动作。
-   附近可见玩家看到该角色动作表现。
-   动作结束恢复常态。

### 【边界与例外】

-   不同地图实例的玩家不会收到该动作事件（关联第5章）。
-   超频请求被服务端拒绝（见 14.5）。
-   动作事件不得用于传递文本或脚本。

### 【验收标准】

1.  同实例可见玩家能收到并播放动作。
2.  不同实例玩家收不到。
3.  超频或非法动作被拒。
4.  动作不携带文本。

## 14.4 社交反馈与附近玩家列表

**优先级：【MVP必须】**

### 【功能说明】

向玩家提供附近玩家列表与实时社交反馈，使非文字社交可被感知。

### 【触发条件】

-   地图内出现/离开可见玩家（事件见第5章）。
-   可见玩家播放动作/表情。

### 【玩家输入】

-   （可选）查看附近玩家列表。

### 【计算/规则】

1.  附近玩家列表由服务端按第5章可见范围计算并下发。
2.  列表中展示玩家公开信息（见 14.2）。
3.  当某可见玩家播放动作时，按 14.3 规则广播并在其角色上表现。
4.  玩家离开可见范围后，从列表与场景表现中移除。
5.  列表刷新频率受第5章联机同步频率约束。

### 【反馈（动画、音效、UI、屏幕表现）】

-   场景内其他玩家头顶显示动作气泡/特效（非文字）。
-   列表实时更新进出。
-   UI 细节见第16章。

### 【边界与例外】

-   可见范围外玩家不进入列表。
-   列表为空时显示空态，不报错。
-   高频进出导致的列表抖动由第5章频率限制平滑。

### 【验收标准】

1.  附近玩家进入/离开列表正确更新。
2.  动作在可见玩家角色上正确表现。
3.  列表仅含可见范围内玩家。
4.  空列表正常展示。

## 14.5 动作频率限制

**优先级：【MVP必须】**

### 【功能说明】

对动作/表情的触发频率进行限制，防止刷屏与带宽滥用。

### 【触发条件】

-   玩家在短时间内连续触发动作。

### 【玩家输入】

连续点击动作。

### 【计算/规则】

1.  服务端对单玩家动作事件设置频率上限（具体阈值待定，由第5章联机频率限制统一定义，关联第3章 3.7）。
2.  超过频率的请求被服务端拒绝，不广播。
3.  频率限制为服务端权威，客户端预校验仅用于体验，不得作为放行依据。
4.  不同动作可配置相同或差异化的频率策略，均以配置表为准。

### 【反馈（动画、音效、UI、屏幕表现）】

-   超频时客户端给出轻量提示（如按钮短暂不可用）。
-   合法动作正常播放。

### 【边界与例外】

-   频率阈值未配置时，使用第5章默认安全值，不放开限制。
-   频率限制不影响正常移动与交互。

### 【验收标准】

1.  超频动作被服务端拒绝。
2.  正常频率动作全部生效。
3.  频率阈值可由配置调整并生效。

## 14.6 【不在本期范围】复杂社交系统

**优先级：【不在本期范围】**

### 【功能说明】

明确首期不实现的社交功能，避免与轻社交系统混淆。

### 【触发条件】

不适用（本期不开发）。

### 【玩家输入】

无。

### 【计算/规则】

以下系统本期不设计、不开发、不纳入验收：

  系统         说明                                     关联依据
  ------------ ---------------------------------------- --------------------------
  文字聊天     自由文本聊天                              G-015、第1章 1.4.3
  好友系统     添加/管理好友关系                         G-015、第1章 1.4.3
  交易系统     玩家间物品/资源交易                       第1章 1.4.3
  公会系统     公会创建/加入/管理                        第1章 1.4.3
  组队系统     玩家组队共同闯关                          第1章 1.4.3、G-015

规则：

1.  以上功能不进入 MVP 任务。
2.  若后续版本引入，须单独建立新系统并明确与轻社交系统的边界。
3.  本期所有社交表达严格限定为非文字、无数值收益的预设动作与表情。

### 【反馈（动画、音效、UI、屏幕表现）】

不适用。

### 【边界与例外】

-   不得通过动作 ID 或表情机制变相实现文字聊天（如用动作序列编码文本）。
-   不得通过社交机制给予数值优势。

### 【验收标准】

1.  本期客户端不包含聊天/好友/交易/公会/组队入口。
2.  所有社交表达均为预设非文字动作/表情。
3.  社交机制不产生数值收益。
